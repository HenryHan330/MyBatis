# 03 接口代理与参数处理

> 本篇是整个 MyBatis 的**分水岭**：学会接口代理，代码量直接砍半；搞懂参数处理，`#{}` 就再也不会写错。

## 1. 先看问题：不用代理时有多难受

```java
public class AccountDaoImpl implements AccountDao {
    @Override
    public Account selectByActno(String actno) {
        SqlSession sqlSession = SqlSessionUtil.openSession();
        // 1. 字符串是硬编码，写错编译不报错
        Account account = sqlSession.selectOne("selectByActno", actno);
        sqlSession.close();
        return account;
    }
}
```

痛点：

1. `"selectByActno"` 是字符串，**编译器不管**，改名后运行才炸。
2. `selectOne` / `insert` / `update` 要程序员自己选对，选错了类型对不上。
3. 每个方法都要写「拿 session、关 session」的模板代码。
4. 接口 + 实现类 + XML 三处维护，冗余。

## 2. MyBatis 的接口代理机制

**做法**：`dao` 层只写**接口**，不写实现类；由 MyBatis 用 `JDK 动态代理` 生成代理对象。

```java
SqlSession sqlSession = SqlSessionUtil.openSession();
// 传入接口的 Class 对象，MyBatis 返回代理对象
CarMapper carMapper = sqlSession.getMapper(CarMapper.class);
Car car = carMapper.selectById(1L);
```

### 2.1 代理生效的 3 个硬性要求

| 要求 | 说明 |
| --- | --- |
| ① `namespace` = 接口**全限定名** | `<mapper namespace="com.jkweilai.mybatis.mapper.CarMapper">` |
| ② `id` = **方法名** | `<select id="selectById">` ↔ `Car selectById(Long id)` |
| ③ 参数类型、返回值类型**一致** | 返回值决定用 `selectOne` 还是 `selectList` |

满足后，`getMapper()` 就会为每个方法生成一个 `MapperProxy`，方法调用 → 找到 `namespace.id` 的 MappedStatement → 执行 → 按方法返回类型封装结果。

### 2.2 完整示例

```java
package com.jkweilai.mybatis.mapper;

import com.jkweilai.mybatis.pojo.Car;
import java.util.List;

public interface CarMapper {
    int insert(Car car);
    int deleteById(Long id);
    int updateById(Car car);
    Car selectById(Long id);
    List<Car> selectAll();
}
```

```xml
<mapper namespace="com.jkweilai.mybatis.mapper.CarMapper">
    <insert id="insert">insert into t_car values(null,#{carNum},#{brand},#{guidePrice},#{produceTime},#{carType})</insert>
    <delete id="deleteById">delete from t_car where id = #{id}</delete>
    <update id="updateById">update t_car set brand = #{brand} where id = #{id}</update>
    <select id="selectById" resultType="Car">select * from t_car where id = #{id}</select>
    <select id="selectAll" resultType="Car">select * from t_car</select>
</mapper>
```

```java
SqlSession sqlSession = SqlSessionUtil.openSession();
CarMapper mapper = sqlSession.getMapper(CarMapper.class);
Car car = mapper.selectById(1L);
sqlSession.commit();
SqlSessionUtil.closeSqlSession();
```

> 代理对象**不需要你管事务和关闭**，但 `commit()` 还是要自己调（除非 session 是 autoCommit）。

## 3. `#{}` 和 `${}` 的区别（重点，面试必问）

| 对比项 | `#{}` | `${}` |
| --- | --- | --- |
| 底层 | `PreparedStatement` 的 `?` 占位符 | 直接**字符串拼接**进 SQL（`Statement`） |
| 是否加引号 | 自动加（字符串类型会包 `''`） | 不加，原样拼 |
| SQL 注入 | **安全** | **有风险** |
| 类型处理 | 走 `TypeHandler`，自动转换 | 无，纯文本 |
| 预编译 | 有（可复用执行计划） | 无 |
| 用途 | 参数值 | 表名、列名、排序字段等 **SQL 结构** |

### 3.1 使用 `#{}`

```xml
<select id="selectById" resultType="Car">
    select * from t_car where id = #{id}
</select>
```

日志：`Preparing: select * from t_car where id = ?` + `Parameters: 1(Long)`

### 3.2 使用 `${}`

```xml
<select id="selectByBrand" resultType="Car">
    select * from t_car where brand = '${brand}'
</select>
```

字符串类型**必须自己加引号**，日志里 SQL 已经被拼好：

```text
Preparing: select * from t_car where brand = '宝马520Li'
```

**注入演示**：如果传入 `brand = "宝马' or '1'='1"`，SQL 变成

```sql
select * from t_car where brand = '宝马' or '1'='1'
```

⇒ 全表数据被查出来。这就是注入。

### 3.3 什么时候非用 `${}` 不可：拼接表名

```xml
<!-- 查询 t_car / t_car_backup，表名不能是 ? 占位符 -->
<select id="selectFromTable" resultType="Car">
    select * from ${tableName}
</select>
```

**为什么表名不能用 `#{}`**：`?` 只能替换**值**，不能替换**标识符**（表名、列名、关键字）。`select * from ?` 是语法错误。

### 3.4 黄金法则

> **能用 `#{}` 就用 `#{}`；
> 只有当需要把「SQL 结构」（表名、列名、`asc/desc`、`in` 的括号等）交给用户输入时，才用 `${}`，并且必须**在服务端做白名单校验**。**

## 4. 模糊查询的两种写法

**第一种：`concat` 函数（推荐，安全）**

```xml
<select id="selectByBrandLike" resultType="Car">
    select * from t_car where brand like concat('%', #{brand}, '%')
</select>
```

**第二种：双引号拼接通配符（`${}` 也行，但要注意引号）**

```xml
<select id="selectByBrandLike2" resultType="Car">
    select * from t_car where brand like "%"#{brand}"%"
</select>
```

> 不要写成 `like '%#{brand}%'` —— `#{}` 在引号内部会被当成字符串字面量，导致查不到数据。

## 5. 参数处理：五种情况必须分清

Mapper 方法能接收什么参数？MyBatis 的处理规则一共 5 种。

### 5.1 单个简单类型参数

```java
Car selectById(Long id);
List<Car> selectByBrand(String brand);
int deleteByBirth(Date birth);
```

```xml
<select id="selectById" resultType="Car">
    select * from t_car where id = #{id}   <!-- 写 #{xyz} 也一样能跑 -->
</select>
```

规则：

- **`#{}` 里写什么都可以**（`#{id}`、`#{value}`、`#{abc}`），因为只有一个占位符，MyBatis 不做名字匹配。
- 老版本（3.5.1 及以前）在**动态 SQL 的 `test` 属性**里必须用 `_parameter` 表示这个参数；**3.5.2 起已修复**，可以直接写参数名。
- 简单类型包括：`byte short int long float double char boolean` 及其包装类、`String`、`java.util.Date`、`BigDecimal` 等。

### 5.2 Map 参数

```java
int insertCar(Map<String, Object> map);
List<Car> selectByMap(Map<String, Object> map);
```

```xml
<select id="selectByMap" resultType="Car">
    select * from t_car where brand = #{brand} and car_type = #{carType}
</select>
```

- `#{}` 里写 **map 的 key**。
- key 不存在 → 插入/比较的是 `NULL`，**不报错**（最坑的地方）。

### 5.3 实体类（POJO）参数

```java
int insert(Car car);
```

```xml
<insert id="insert">
    insert into t_car values(null, #{carNum}, #{brand}, #{guidePrice}, #{produceTime}, #{carType})
</insert>
```

- 写**属性名**（不是 `getCarNum`），底层通过 getter 取值。
- 嵌套属性可以用 `#{clazz.cname}` 这种写法。

### 5.4 多个参数

```java
List<Car> selectByBrandAndType(String brand, String carType);
List<Car> selectByTimeRange(Date begin, Date end);
```

```xml
<select id="selectByBrandAndType" resultType="Car">
    select * from t_car where brand = #{arg0} and car_type = #{arg1}
    <!-- 也可以写成 #{param1} 和 #{param2} -->
</select>
```

规则（牢记）：

- MyBatis 会把多个参数封装成一个 `Map`，key 是 **`arg0`、`arg1`、...** 和 **`param1`、`param2`、...**（两套 key 都指向同一个值）。
- MyBatis **3.4.1 之前**是 `0`、`1`，**3.4.1 起**改为 `arg0`、`arg1`。
- 直接写 `#{brand}` 会报 `There is no getter for property named 'brand' in 'class org.apache.ibatis.binding.MapperMethod$ParamMap'`。

### 5.5 `@Param` 命名参数（推荐）

```java
List<Car> selectByBrandAndType(@Param("brand") String brand, @Param("carType") String carType);
```

```xml
<select id="selectByBrandAndType" resultType="Car">
    select * from t_car where brand = #{brand} and car_type = #{carType}
</select>
```

规则：

- 用了 `@Param` 之后，`#{}` 里**必须用注解里的名字**，`arg0`/`param1` **失效**。
- 可读性最好，动态 SQL 的 `test` 里也好写，**实际开发首选**。
- 如果方法是 `POJO + 其他参数` 混用，POJO 也建议加 `@Param`。

**五种传参速查**

| 场景 | `#{}` 里写什么 | 建议 |
| --- | --- | --- |
| 单个简单类型 | 任意 | 写个有意义的名字即可 |
| `Map` | key | key 别写错 |
| POJO | 属性名 | 保证有 getter |
| 多参数 | `arg0/arg1` 或 `param1/param2` | **改用 `@Param`** |
| `@Param` | 注解里的名字 | **首选** |

## 6. `typeAliases`：给类型起别名

### 6.1 方式一：单个起别名

```xml
<typeAliases>
    <typeAlias type="com.jkweilai.mybatis.pojo.Car" alias="Car"/>
</typeAliases>
```

之后 `resultType="Car"` 即可（大小写不敏感，`car` 也行）。

### 6.2 方式二：按包批量起别名（推荐）

```xml
<typeAliases>
    <package name="com.jkweilai.mybatis.pojo"/>
</typeAliases>
```

规则：**类名首字母小写**作为别名，`Car` → `car`，`UserInfo` → `userInfo`。也可以类上加 `@Alias("car")` 覆盖。

### 6.3 内置别名（不用配就能用）

| 别名 | 类型 |
| --- | --- |
| `string` | `java.lang.String` |
| `int` / `integer` | `java.lang.Integer` |
| `long` / `double` / `float` | 对应包装类 |
| `date` | `java.util.Date` |
| `map` | `java.util.Map` |
| `list` | `java.util.List` |
| `decimal` / `bigdecimal` | `java.math.BigDecimal` |

> 要注意的坑：`Car` 这个类名如果没配别名，`resultType="Car"` 会报 `ClassNotFoundException: Car`（找不到就叫 `com.jkweilai.mybatis.pojo.Car`）。

## 7. 本篇小结

1. **接口代理**：`namespace` = 接口全限定名、`id` = 方法名，参数与返回值一致，`sqlSession.getMapper(Xxx.class)`。
2. **`#{}` 优于 `${}`**：前者预编译防注入，后者只用于「SQL 结构」且必须白名单校验。
3. **五种传参**：单简单类型（名字随意）→ Map（写 key）→ POJO（写属性名）→ 多参数（`arg0`/`param1`）→ `@Param`（最佳）。
4. **别名**能少写全限定名，但别把 `resultType` 写成一个不存在的别名。
