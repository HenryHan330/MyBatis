# 11 MP 进阶特性

> 本篇是 MP 的「日常开发够用」清单：**分页插件、逻辑删除、枚举处理器、JSON 处理器、Db 工具类、代码生成器**。

## 1. 分页插件

MP 的分页插件能自动把 `Page` 对象转换成数据库的分页 SQL（`limit`），**不用手写 limit，也不用 PageHelper**。

### 1.1 第一步：引入依赖（3.5.9+ 必须单独引）

```xml
<dependency>
  <groupId>com.baomidou</groupId>
  <artifactId>mybatis-plus-jsqlparser</artifactId>
  <version>3.5.11</version>
</dependency>
```

> **3.5.9 起分页插件被拆到 `mybatis-plus-jsqlparser`**，只引 starter 会**分页不生效**（SQL 不带 `limit`，返回全部数据），
> 这是升级 MP 后最常见的坑。

### 1.2 第二步：配置拦截器

```java
@Configuration
public class MyBatisConfig {

    // MP 插件机制底层基于 MyBatis 的 Interceptor 实现
    @Bean
    public MybatisPlusInterceptor mybatisPlusInterceptor() {
        // 拦截器链：集中管理 MP 的各种内部拦截器
        MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();

        // 分页拦截器，指定数据库类型（MySQL 生成 LIMIT）
        PaginationInnerInterceptor pageInterceptor = new PaginationInnerInterceptor(DbType.MYSQL);

        // 单页最大记录数：pageSize 超过 500 时自动按 500 处理，防止 pageSize=100000 打爆内存
        pageInterceptor.setMaxLimit(500L);

        // 分页拦截器通常放在最后
        interceptor.addInnerInterceptor(pageInterceptor);
        return interceptor;
    }
}
```

### 1.3 第三步：使用

```java
@Test
void testPage() {
    int pageNo = 1;
    int pageSize = 2;

    // 1. 创建分页对象
    Page<Car> page = Page.of(pageNo, pageSize);

    // 2. 指定排序：先按 guide_price 升序，价格相同按 id 降序
    page.addOrder(OrderItem.asc("guide_price"));
    page.addOrder(OrderItem.desc("id"));

    // 3. 执行分页（可传条件 Wrapper，也可以不传）
    carService.page(page);

    // 4. 从 page 里取分页信息
    System.out.println("总记录条数：" + page.getTotal());
    System.out.println("总页数：" + page.getPages());
    System.out.println("当前页：" + page.getCurrent());
    System.out.println("每页条数：" + page.getSize());
    List<Car> records = page.getRecords();
    records.forEach(System.out::println);
}
```

**要点**

- `page(page)` 会**改写原 SQL 拼 `limit`**，并**额外执行一次 `count`** 得到 `total`。
- `Page` 是入参也是出参：**分页结果写回同一个对象**（`records`、`total`、`pages`）。
- 排序也可以写进 `Wrapper`：`wrapper.orderByDesc(Car::getId)`。
- `page(page, wrapper)` 与 `page(page)` 的区别只是带不带条件。
- 分页对象是**线程不安全的**，每次请求 `Page.of(...)` 新建即可。

## 2. 逻辑删除

### 2.1 是什么

**不真正删数据**，只把某条记录标记为「已删除」（如 `deleted = 1`）。

```sql
-- 删除变成 update
update t_wx set deleted = 1 where id = ?;

-- 查询都要带上条件
select * from t_wx where deleted = 0;
```

**什么时候用**：数据重要、需要追溯时。
**为什么不推荐滥用**：数据量只增不减，越来越慢，索引也会膨胀。
如果确实要保留，更好的做法是**把删除的数据迁移到备份表**。

### 2.2 配置

```yaml
mybatis-plus:
  global-config:
    db-config:
      logic-delete-field: deleted   # 逻辑删除字段名
      logic-delete-value: 1         # 已删除
      logic-not-delete-value: 0     # 未删除
```

实体类加上字段（也可以显式加 `@TableLogic`）：

```java
@TableLogic
private Integer deleted;
```

表结构：`deleted int NOT NULL DEFAULT 0`。

### 2.3 生效效果

```java
weiXiuService.removeById(2L);      // 实际执行 update t_wx set deleted=1 where id=2 and deleted=0
WeiXiu w = weiXiuService.getById(2L);  // 实际执行 ... where id=2 and deleted=0 ⇒ 查不到
```

- **`delete` 自动变 `update`**；
- **所有 `select` 自动追加 `deleted = 0`**；
- `insert` 不用管，为 `null` 时由数据库默认值补 0。

### 2.4 逻辑删除的坑

| 坑 | 说明 |
| --- | --- |
| 唯一索引冲突 | 逻辑删除后那条记录还在，唯一索引仍然占位，无法再插入相同业务键 |
| 手写 SQL 忘了加条件 | 自定义 XML 里 MP **不会自动加** `deleted=0`，必须自己写 |
| 联表查询 | 关联表的逻辑删除条件也要自己处理 |
| 数据量膨胀 | 一定要配定期归档任务 |

## 3. 枚举处理器

### 3.1 问题：数字状态可读性差

汽车状态：`1` 在售、`2` 已售、`3` 维修中、`4` 报废，数据库字段 `status int`。
如果 PO 里也定义成 `Integer`，代码里全是 `if (status == 2)` —— 谁记得 `2` 是什么？

### 3.2 第一步：定义枚举

```java
@Getter
public enum CarStatus {
    FOR_SALE(1, "在售"),
    SOLD(2, "已售"),
    IN_MAIN(3, "维修中"),
    SCRAP(4, "报废");

    @EnumValue          // ✅ 标记：把哪个属性的值存到数据库
    private final int value;
    private final String desc;

    CarStatus(int value, String desc) {
        this.value = value;
        this.desc = desc;
    }
}
```

> 想让**接口返回中文**而不是 `1/2/3/4`，在 `desc` 上加 `@JsonValue`：
>
> ```java
> @JsonValue
> private final String desc;
> ```
>
> **注意**：加了 `@JsonValue` 之后，前端提交 JSON 时 `status` 必须传中文 `"在售"`，
> 否则新增接口会报枚举转换异常。

### 3.3 第二步：配置全局枚举处理器

```yaml
mybatis-plus:
  configuration:
    default-enum-type-handler: com.baomidou.mybatisplus.core.handlers.MybatisEnumTypeHandler
```

### 3.4 效果

```java
Car car = new Car();
car.setStatus(CarStatus.SOLD);   // 可读性拉满
carService.save(car);            // 数据库里存 2

Car c = carService.getById(1L);  // 数据库 1 → CarStatus.FOR_SALE
```

- 写入：枚举 → `@EnumValue` 标注的值；
- 读取：数据库值 → 对应的枚举常量；
- `MybatisEnumTypeHandler` 是 MP 提供的转换器，只需注册，无需自己写 `TypeHandler`。

> 注意区分：`@EnumValue` 管的是「**哪个值存库**」，`@JsonValue` 管的是「**序列化成 JSON 时输出什么**」。
> 两者独立，按需组合。

## 4. JSON 处理器

### 4.1 场景

`t_car.owner` 是 `json` 类型，存车主信息：

```json
{"id": "909890989898767676", "name": "张三"}
```

实体类里用什么类型接？

1. 用 `String` —— 能接，但**在 Java 里操作 JSON 字符串很难受**；
2. **定义一个对应的实体类** `Owner` —— 推荐，对象操作比字符串方便。

但默认情况下 MyBatis 不会把 JSON 字符串自动转成 `Owner` 对象，所以需要 **JSON 类型处理器**。

### 4.2 第一步：定义 JSON 对应的实体

```java
@Data
@NoArgsConstructor
@AllArgsConstructor(staticName = "of")   // 生成静态方法 of(...)，方便创建
public class Owner {
    private String id;
    private String name;
}
```

### 4.3 第二步：实体类上标注（两个地方都要改）

```java
@Data
@TableName(value = "t_car", autoResultMap = true)   // ✅ 必须开 autoResultMap
public class Car {
    @TableId(value = "id", type = IdType.AUTO)
    private Long id;
    private String carNum;
    private String brand;
    private BigDecimal guidePrice;
    private String produceTime;
    private String carType;
    private CarStatus status;

    @TableField(typeHandler = JacksonTypeHandler.class)   // ✅ 指定 JSON 处理器
    private Owner owner;
}
```

- **`autoResultMap = true` 是前提**：不开启，`typeHandler` 只在写入时生效，**查询时不会生效**（查出来是 null）。
- MP 提供多种 JSON 处理器：`JacksonTypeHandler`（推荐，Spring Boot 默认集成 Jackson）、`FastjsonTypeHandler`、`GsonTypeHandler`。
  选 `JacksonTypeHandler` 就不用额外引入 JSON 库。

### 4.4 第三步：VO 同步加字段

```java
@Schema(description = "车主信息")
private Owner owner;
```

### 4.5 测试

```java
@Test
public void testSave() {
    Car car = new Car();
    car.setCarNum("津A90909");
    car.setCarType("新能源");
    car.setBrand("BYD666");
    car.setProduceTime("2025-10-11");
    car.setStatus(CarStatus.FOR_SALE);
    car.setGuidePrice(BigDecimal.valueOf(20));
    // 车辆关联车主（对象直接塞进去，底层序列化成 JSON）
    car.setOwner(Owner.of("890989098989876787", "达摩"));
    carService.save(car);
}
```

查询时，`car.getOwner()` 直接就是 `Owner` 对象，不用自己 `JSON.parse`。

> **常见坑**：只加了 `typeHandler` 没加 `autoResultMap = true` ⇒ 插入正常、查询为 `null`。
> 另一个坑：用了 `@TableName(autoResultMap = true)` 之后，**该实体所有 `resultMap` 都会自动生成**，
> 如果还有自定义 XML 的 `resultMap`，注意别冲突。

## 5. `Db` 静态工具类

### 5.1 它解决什么问题：循环依赖

现在有两张表：

- `t_car`：汽车
- `t_wx`：维修记录（`car_id` 关联 `t_car.id`）

关系是**一对多**：一辆车有多条维修记录。于是有两个 service：`CarService`、`WeiXiuService`。

需求：

1. 按汽车 id 查汽车 + 它的所有维修记录 ⇒ `CarServiceImpl` 要注入 `WeiXiuService`；
2. 按维修 id 查维修记录 + 它关联的汽车 ⇒ `WeiXiuServiceImpl` 要注入 `CarService`。

**结果：循环依赖**（Spring 启动可能报 `The dependencies of some of the beans in the application context form a cycle`，
即使能启动也是非常糟糕的设计）。

### 5.2 `Db` 的用法

**`Db` 是一个静态工具类**，方法基本就是 `IService` 的那一套，区别是**多一个 `Class` 参数**：

> 因为 `IService` 能靠泛型确定实体类型，而**静态方法无法使用泛型**，只能显式传 `Class`。

```java
// IService 里：Service 自己知道泛型
lambdaQuery().eq(Car::getBrand, "宝马").list();

// Db 里：必须告诉它操作哪个实体
Db.lambdaQuery(Car.class).eq(Car::getBrand, "宝马").list();
```

### 5.3 完整示例：查汽车 + 带出维修记录

**实体**

```java
@Data
@TableName("t_wx")
public class WeiXiu {
    @TableId(value = "id", type = IdType.AUTO)
    private Long id;
    @TableField("`time`")     // time 是 MySQL 关键字
    private String time;
    private Double cost;
    private String description;
    private Long carId;
    @TableLogic
    private Integer deleted;
}
```

**CarService 里直接查，不用注入 WeiXiuService**

```java
@Override
public CarVO queryCarAndWeiXiuById(Long id) {
    // 1. 查车辆
    Car car = getById(id);
    if (car == null) {
        throw new RuntimeException("车辆信息异常！");
    }
    // 2. 用 Db 查维修记录（这里原本要依赖 WeiXiuService）
    List<WeiXiu> weiXiuList = Db.lambdaQuery(WeiXiu.class)
            .eq(WeiXiu::getCarId, car.getId())
            .list();
    // 3. PO → VO
    CarVO carVO = BeanUtil.copyProperties(car, CarVO.class);
    carVO.setWeiXiuList(BeanUtil.copyToList(weiXiuList, WeiXiuVO.class));
    return carVO;
}
```

**`CarVO` 里加集合字段**

```java
@Schema(description = "维修记录列表")
private List<WeiXiuVO> weiXiuList;
```

**Controller**

```java
@Operation(summary = "查询车辆信息以及该车辆的维修记录",
        parameters = @Parameter(name = "id", description = "车辆id"))
@GetMapping("queryById/{id}")
public CarVO queryCarAndWeiXiuById(@PathVariable("id") Long id) {
    return carService.queryCarAndWeiXiuById(id);
}
```

**`Db` 常用方法**（与 `IService` 一一对应，但都多一个 `Class` 参数）

| 方法 | 说明 |
| --- | --- |
| `Db.getById(Class, id)` | 按主键查 |
| `Db.listByIds(Class, ids)` | 批量查 |
| `Db.save(entity)` | 保存（实体自带类型，不需要 Class） |
| `Db.removeById(Class, id)` | 按主键删 |
| `Db.lambdaQuery(Class)` | 链式条件查询 |
| `Db.lambdaUpdate(Class)` | 链式条件更新 |
| `Db.page(Class, Page)` | 分页 |

> `Db.save(obj)` / `Db.updateById(obj)` 这类方法不需要 `Class`，因为对象本身能取出类型。

## 6. 代码生成器 / 逆向工程

MP 官方推荐两种方式：

1. **自己写代码生成**（参考官方文档 `AutoGenerator`，适合批量生成）；
2. **装 MyBatisX 插件**（IDEA 里最省事，日常首选）。

### 6.1 用 MyBatisX 插件生成

1. IDEA → `Settings` → `Plugins` → 搜索 **MyBatisX** → 安装并重启；
2. 在 IDEA 右侧 `Database` 面板连上 MySQL，展开到具体表；
3. 在表名上右键 → **MyBatisX-Generator**；
4. 填写：模块路径、包名（`com.jkweilai.mp`）、表名、实体名、模板（`mybatis-plus3`）；
5. 勾选需要生成的内容（PO / Mapper / Service / ServiceImpl / Controller），生成即可。

生成出来的结构：

```text
entity/Car.java            → @TableName("t_car") + Lombok + 字段注解
mapper/CarMapper.java      → extends BaseMapper<Car>
service/CarService.java    → extends IService<Car>
service/impl/CarServiceImpl.java → extends ServiceImpl<CarMapper, Car>
```

> 生成后要自己检查三件事：**主键策略是否 `AUTO`**、**关键字列是否加反引号**、**包名/`@MapperScan` 是否一致**。

## 7. 本篇小结（MP 最佳实践）

1. **分页**：3.5.9+ 要单独引 `mybatis-plus-jsqlparser`，再注册 `PaginationInnerInterceptor`，并设 `setMaxLimit`。
2. **逻辑删除**：配置 `logic-delete-field` 即可让 `delete` 变 `update`、查询自动过滤；**自定义 SQL 不生效，要自己写**。
3. **枚举**：枚举里 `@EnumValue` 标存库字段，`@JsonValue` 标对外输出，全局注册 `MybatisEnumTypeHandler`。
4. **JSON**：`@TableName(autoResultMap = true)` + `@TableField(typeHandler = JacksonTypeHandler.class)`，缺一不可。
5. **`Db` 工具类**：跨 Service 调用时避免循环依赖，方法与 `IService` 一致、多一个 `Class` 参数。
6. **代码生成**：直接上 MyBatisX 插件，比手写 `AutoGenerator` 快得多。
7. 记住 MP 的边界：**单表用它，多表写 XML**。官方文档说「MP 掌握这些，完全可以应付日常开发」，前提也是这个边界。
