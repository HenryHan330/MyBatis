# 06 高级映射与延迟加载

> 前面都是单表。真实业务几乎躲不开多表：本篇用 `t_student(sid, sname, cid)` 和 `t_clazz(cid, cname)` 讲清
> **多对一**（多个学生属于一个班）和 **一对多**（一个班有多个学生）。

```sql
create table t_clazz(cid int primary key, cname varchar(255));
insert into t_clazz values (1001, '高三1班'), (1002, '高三2班');

create table t_student(sid int primary key auto_increment, sname varchar(255), cid int);
insert into t_student(sname, cid) values ('张三',1001),('李四',1001),('王五',1001),('赵六',1002),('钱七',1002);
```

## 1. 多对一：三种写法

需求：查学生，同时把学生所属的**班级信息**也查出来。

### 1.1 写法一：级联属性映射（最直观）

```xml
<resultMap id="studentResultMap" type="Student">
    <id property="sid" column="sid"/>
    <result property="sname" column="sname"/>
    <!-- 级联：把 clazz 对象的属性直接映射出来 -->
    <result property="clazz.cid"   column="cid"/>
    <result property="clazz.cname" column="cname"/>
</resultMap>

<select id="selectAll" resultMap="studentResultMap">
    select s.sid, s.sname, s.cid, c.cname
    from t_student s left join t_clazz c on s.cid = c.cid
</select>
```

- `property="clazz.cid"` 表示「`Student` 里的 `clazz` 属性的 `cid` 属性」。
- **要求**：`Student` 里必须有 `Clazz clazz` 字段，且 `clazz` **已经实例化**（`private Clazz clazz = new Clazz();`），
  否则会抛 `NullPointerException`（MyBatis 不会自动 new 这个嵌套对象）。

### 1.2 写法二：`<association>`（推荐，语义清晰）

```xml
<resultMap id="studentResultMap2" type="Student">
    <id property="sid" column="sid"/>
    <result property="sname" column="sname"/>
    <!-- javaType 指定这个属性的类型，不可省略 -->
    <association property="clazz" javaType="Clazz">
        <id property="cid" column="cid"/>
        <result property="cname" column="cname"/>
    </association>
</resultMap>
```

- `association` 专门用于「**一**」的一方，`javaType` 必须写。
- 内部同样可以用 `<id>` / `<result>`。

### 1.3 写法三：分步查询（`select` 属性）

```xml
<resultMap id="studentResultMap3" type="Student">
    <id property="sid" column="sid"/>
    <result property="sname" column="sname"/>
    <!-- column="cid"：把当前结果集的 cid 列，作为参数传给下面的 selectById -->
    <association property="clazz"
                 column="cid"
                 select="com.jkweilai.mybatis.mapper.ClazzMapper.selectById"/>
</resultMap>

<select id="selectAllStep" resultMap="studentResultMap3">
    select sid, sname, cid from t_student
</select>

<select id="selectById" resultType="Clazz">
    select cid, cname from t_clazz where cid = #{cid}
</select>
```

- 先查学生（1 条 SQL），再**按每个学生的 cid 各查一次**班级（N 条 SQL）→ 这就是著名的 **N+1 问题**。
- 分步查询的价值：可以配合**延迟加载**，用不到班级时就不查。

## 2. 一对多：`<collection>`

需求：查班级，同时把班级下的**所有学生**查出来。

### 2.1 写法一：`<collection>` + 连接查询

```xml
<resultMap id="clazzResultMap" type="Clazz">
    <id property="cid" column="cid"/>
    <result property="cname" column="cname"/>
    <!-- ofType：集合里元素的类型 -->
    <collection property="students" ofType="Student">
        <id property="sid" column="sid"/>
        <result property="sname" column="sname"/>
    </collection>
</resultMap>

<select id="selectClazzWithStudents" resultMap="clazzResultMap">
    select c.cid, c.cname, s.sid, s.sname
    from t_clazz c left join t_student s on c.cid = s.cid
</select>
```

- `property`：集合属性名；`ofType`：集合**元素**的类型（不是 `javaType`）。
- 用 `left join` 保证没有学生的班级也能查出来（此时 `students` 是空集合）。

> **必须写 `<id>`**！MyBatis 靠 `<id>` 判断「哪些行属于同一个 Clazz」，从而合并成一个对象。不写 `<id>` 会把每条记录都当成一个新班级。

### 2.2 写法二：分步查询（`collection + select`）

```xml
<resultMap id="clazzResultMap2" type="Clazz">
    <id property="cid" column="cid"/>
    <result property="cname" column="cname"/>
    <collection property="students"
                ofType="Student"
                column="cid"
                select="com.jkweilai.mybatis.mapper.StudentMapper.selectByCid"/>
</resultMap>

<select id="selectClazzStep" resultMap="clazzResultMap2">
    select cid, cname from t_clazz
</select>

<select id="selectByCid" resultType="Student">
    select sid, sname from t_student where cid = #{cid}
</select>
```

## 3. 延迟加载（懒加载）

**现象**：分步查询时，我只想要班级名，但 MyBatis 把每个班的学生也全查了一遍 —— 白查。

**配置**（`mybatis-config.xml` 的 `settings`）：

```xml
<settings>
    <!-- 开启全局延迟加载，默认 false -->
    <setting name="lazyLoadingEnabled" value="true"/>
    <!-- 关闭「按需加载的侵略性」，默认 true；true 时调用任意方法都会触发全部延迟加载 -->
    <setting name="aggressiveLazyLoading" value="false"/>
</settings>
```

**局部控制**：用 `fetchType` 覆盖全局配置

```xml
<!-- 按需：用到了才查 -->
<association property="clazz" column="cid"
             select="...ClazzMapper.selectById" fetchType="lazy"/>

<!-- 立即查：不管用不用 -->
<collection property="students" ofType="Student" column="cid"
            select="...StudentMapper.selectByCid" fetchType="eager"/>
```

| `fetchType` | 说明 |
| --- | --- |
| `lazy` | 延迟加载，访问该属性时才发 SQL |
| `eager` | 立即加载 |

**注意**

- 延迟加载**只对「分步查询」有效**，`<association>`/`<collection>` 里用连接查询（嵌套 resultMap 写法）是一次 SQL 查完的，谈不上延迟。
- 延迟加载依赖**代理对象**，如果实体类是 `final` 或者属性是 `private` 且无 getter，可能失效。
- 在 Spring Boot 里等价配置是 `mybatis-plus.configuration.lazy-loading-enabled` 等。

## 4. N+1 问题怎么选

| 方案 | SQL 条数 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 连接查询（join + resultMap） | 1 | 快，无 N+1 | 结果集有冗余，分页时行数会错（一对多 join 后分页要对主表分页） |
| 分步查询 + 立即加载 | N+1 | 结构清晰、SQL 简单 | 网络往返多，慢 |
| 分步查询 + 延迟加载 | 按需 | 不用就不查 | 容易「在循环里触发查询」，变成 N 次 |
| 分步查询 + 批量（`<foreach>` 或 MP 的 `listByIds`） | 2 | 兼顾清晰与性能 | 需要自己组装 |

> 实战建议：**列表页用连接查询或「两次查询（先查主表 → 收集 id → in 查从表 → 内存组装）」**；
> 详情页用分步查询 + 延迟加载。

## 5. 本篇小结

1. **多对一** → `<association javaType="...">`；**一对多** → `<collection ofType="...">`。
2. 三种实现：**级联属性**（要求嵌套对象已实例化）、**嵌套 resultMap**（一条 SQL）、**分步查询**（多条 SQL）。
3. 分步查询 + `lazyLoadingEnabled` 才是真正的延迟加载；全局开关 `lazyLoadingEnabled=true` + `aggressiveLazyLoading=false`。
4. **`<collection>` 一定要写 `<id>`**，否则同一个班级会被拆成多个对象。
