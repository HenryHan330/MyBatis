# 01 概述与入门程序

> 本篇要解决的事：搞清楚 MyBatis 站在哪、为什么会有它、以及用 6 步跑通第一个程序。

## 1. 三层架构里的 MyBatis

| 层 | 职责 | 常用技术 |
| --- | --- | --- |
| 表现层（Web / 控制层） | 接收请求、展示结果 | Servlet、Spring MVC、Thymeleaf |
| 业务逻辑层（Service） | 业务规则、事务边界 | 自己写的 Service |
| 持久层（Dao / Mapper） | 和数据库打交道 | **JDBC、MyBatis、Hibernate/JPA** |

MyBatis 属于**持久层框架**，它替代的是 JDBC，不是 Service，也不管页面。

## 2. 为什么不用 JDBC：6 个痛点

1. **硬编码**：`url`、`username`、`password`、SQL 都写死在 Java 里，改环境要改代码重新编译。
2. **重复代码**：加载驱动、获取连接、释放资源，每个方法都要写一遍。
3. **结果集封装麻烦**：`ResultSet` → Java 对象要手写 `rs.getString("car_num")`，字段一多就是灾难。
4. **SQL 与 Java 混在一起**：字符串拼接，改 SQL 容易漏空格、漏逗号。
5. **事务、连接池自己实现**：`setAutoCommit(false)`、`commit`、`rollback` 全靠手写。
6. **没有缓存、没有延迟加载**：同样的查询每次都要打数据库。

> 一句话：JDBC 什么都能干，但什么都要你自己干。MyBatis 就是把「重复但必须做」的事包掉。

## 3. MyBatis 是什么

- Apache 顶级开源项目，官网 `https://mybatis.org/`。
- **半自动 ORM 框架**：SQL 仍然由程序员写（XML 或注解），但**参数映射、结果集映射、事务、缓存、连接管理**交给框架。
- 支持定制化 SQL、存储过程、高级映射；复杂查询可以完全手写，因此比 Hibernate/JPA 更可控。
- 「ORM（Object Relational Mapping，对象关系映射）」= Java 对象 ↔ 数据库表记录的映射；MyBatis 更准确的说法是 **SQL Mapping**。

## 4. 第一个 MyBatis 程序：六步走

| 步骤 | 做什么 |
| --- | --- |
| 1 | 建库建表 + 数据 |
| 2 | 建 Maven 工程，引入 `mybatis` + MySQL 驱动 |
| 3 | 写核心配置文件 `mybatis-config.xml` |
| 4 | 写 SQL 映射文件 `XxxMapper.xml` |
| 5 | 写 Java 程序：`Resources` → `SqlSessionFactoryBuilder` → `SqlSessionFactory` → `SqlSession` → 执行 |
| 6 | 提交事务、关闭 `SqlSession` |

### 4.1 建表

```sql
CREATE TABLE `t_car` (
  `id`           bigint NOT NULL AUTO_INCREMENT COMMENT '主键自增',
  `car_num`      varchar(255) COMMENT '车牌号',
  `brand`        varchar(255) COMMENT '品牌',
  `guide_price`  decimal(10,2) COMMENT '指导价：万',
  `produce_time` char(10) COMMENT '出厂日期',
  `car_type`     varchar(255) COMMENT '汽车类型：燃油车 电车 氢能源',
  PRIMARY KEY (`id`)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4;
```

### 4.2 pom.xml

```xml
<dependencies>
    <!-- MyBatis -->
    <dependency>
        <groupId>org.mybatis</groupId>

        <version>3.5.19</version>

        <version>8.0.24</version>
        <scope>runtime</scope>
    </dependency>
</dependencies>
```

### 4.3 mybatis-config.xml（放在 `src/main/resources` 根目录）

```xml
<?xml version="1.0" encoding="UTF-8" ?>
<!DOCTYPE configuration
        PUBLIC "-//mybatis.org//DTD Config 3.0//EN"
        "http://mybatis.org/dtd/mybatis-3-config.dtd">
<configuration>
    <environments default="development">
        <environment id="development">
            <transactionManager type="JDBC"/>
            <dataSource type="POOLED">
                <property name="driver" value="com.mysql.cj.jdbc.Driver"/>
                <property name="url" value="jdbc:mysql://localhost:3306/mybatis"/>
                <property name="username" value="root"/>
                <property name="password" value="root"/>
            </dataSource>
        </environment>
    </environments>

    <mappers>
        <mapper resource="CarMapper.xml"/>
    </mappers>
</configuration>
```

> **坑**：`mybatis-config.xml` 里标签**有顺序要求**，官方 DTD 规定顺序为
> `properties → settings → typeAliases → typeHandlers → objectFactory → objectWrapperFactory → reflectorFactory → plugins → environments → databaseIdProvider → mappers`。
> 顺序写错会报 `The content of element type "configuration" must match ...`。

### 4.4 CarMapper.xml

```xml
<?xml version="1.0" encoding="UTF-8" ?>
<!DOCTYPE mapper
        PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN"
        "http://mybatis.org/dtd/mybatis-3-mapper.dtd">
<mapper namespace="car">
    <insert id="insertCar">
        insert into t_car(id, car_num, brand, guide_price, produce_time, car_type)
        values(null, '1001', '宝马520Li', 10.0, '2020-10-11', '燃油车')
    </insert>
</mapper>
```

- `namespace`：**必须唯一**，用来区分不同文件里同名的 SQL id。
- `id`：这条 SQL 的唯一标识，`sqlSession.insert("insertCar")` 就是按 id 找。

### 4.5 执行程序

```java
public class InsertTest {
    public static void main(String[] args) throws Exception {
        // 1. 获取 SqlSessionFactoryBuilder（构建器，用完即丢）
        SqlSessionFactoryBuilder builder = new SqlSessionFactoryBuilder();
        // 2. 读取核心配置，构建 SqlSessionFactory（重量级，应用级单例）
        InputStream in = Resources.getResourceAsStream("mybatis-config.xml");
        SqlSessionFactory factory = builder.build(in);
        // 3. 打开 SqlSession（轻量级，请求/方法级）
        SqlSession sqlSession = factory.openSession();
        // 4. 执行 SQL（namespace 唯一时可省略，直接写 id）
        int count = sqlSession.insert("insertCar");
        System.out.println("插入记录条数：" + count);
        // 5. 提交事务（MyBatis 默认不自动提交！）
        sqlSession.commit();
        // 6. 关闭
        sqlSession.close();
    }
}
```

> **最大的坑**：`openSession()` 默认 **`autoCommit = false`**。忘了 `commit()`，程序不报错，但数据没进库。
> 想自动提交用 `factory.openSession(true)`，但**不推荐**（事务不好控制）。

## 5. 改良：`SqlSessionUtil` 工具类

每次手写 6 步太啰嗦，`SqlSessionFactory` 只需要构建一次（构建过程很重，要去解析 XML、解析所有 SQL）。

```java
package com.jkweilai.mybatis.utils;

import org.apache.ibatis.io.Resources;
import org.apache.ibatis.session.SqlSession;
import org.apache.ibatis.session.SqlSessionFactory;
import org.apache.ibatis.session.SqlSessionFactoryBuilder;

import java.io.IOException;
import java.io.InputStream;

public class SqlSessionUtil {

    // 类加载时执行一次，SqlSessionFactory 全局唯一
    private static final SqlSessionFactory SQL_SESSION_FACTORY;

    static {
        try {
            SqlSessionFactoryBuilder builder = new SqlSessionFactoryBuilder();
            InputStream in = Resources.getResourceAsStream("mybatis-config.xml");
            SQL_SESSION_FACTORY = builder.build(in);
        } catch (IOException e) {
            // 静态代码块里不能抛受检异常，包装成运行时异常
            throw new RuntimeException(e);
        }
    }

    // ThreadLocal：保证同一线程（同一次请求 / 同一个 service 方法）拿到同一个 SqlSession
    private static final ThreadLocal<SqlSession> THREAD_LOCAL = new ThreadLocal<>();

    private SqlSessionUtil() {
    }

    public static SqlSession openSession() {
        SqlSession sqlSession = THREAD_LOCAL.get();
        if (sqlSession == null) {
            sqlSession = SQL_SESSION_FACTORY.openSession();
            THREAD_LOCAL.set(sqlSession);
        }
        return sqlSession;
    }

    public static void closeSqlSession() {
        SqlSession sqlSession = THREAD_LOCAL.get();
        if (sqlSession != null) {
            sqlSession.close();
            THREAD_LOCAL.remove(); // 必须 remove，否则线程池复用线程时会内存泄漏 / 拿到已关闭的 session
        }
    }
}
```

**为什么用 `ThreadLocal`**

- `SqlSession` **不是线程安全的**，不能做成员变量，也不能塞进 `HttpSession`。
- 一个 service 方法里可能调多次 dao，如果每次 `openSession()` 就是**不同的事务**，转账就转出「钱扣了、没到账」。
- `ThreadLocal` 把 `SqlSession` 绑在「当前线程」上，service 与 dao 共享同一个会话 ⇒ 同一事务。

## 7. 启用标准日志（看 SQL 神器）

在 `mybatis-config.xml` 的 `settings` 里配置（`settings` 必须放在 `environments` 前面）：

```xml
<settings>
    <setting name="logImpl" value="STDOUT_LOGGING"/>
</settings>
```

控制台会输出：

```text
==>  Preparing: insert into t_car(...) values(...)
==> Parameters: 
<==    Updates: 1
```

- `Preparing`：真正发给数据库的 SQL（`#{}` 已被替换成 `?`）
- `Parameters`：实际参数值
- `Updates` / `Total`：影响行数 / 查询条数

这是排查「SQL 到底执行没执行、参数传对没传对」的第一手段，**建议所有练习项目都开着**。

> 其它可选值：`SLF4J`、`LOG4J2`、`LOG4J`、`JDK_LOGGING`、`COMMONS_LOGGING`、`NO_LOGGING`、`STDOUT_LOGGING`。

## 8. 三个核心对象的生命周期（重要）

| 对象 | 作用域 | 说明 |
| --- | --- | --- |
| `SqlSessionFactoryBuilder` | **方法作用域** | 只为创建 `SqlSessionFactory` 而生，创建完就可以丢 |
| `SqlSessionFactory` | **应用作用域（单例）** | 一旦创建就存在整个应用运行期间，不要重复创建 |
| `SqlSession` | **请求 / 方法作用域** | 非线程安全，绝对不能做静态域或实例变量，也绝不能放 `HttpSession` |

标准写法（官方推荐）：

```java
SqlSession sqlSession = sqlSessionFactory.openSession();
try {
    // do work
    sqlSession.commit();
} finally {
    sqlSession.close();   // 关闭必须放 finally
}
```

## 9. 入门阶段最常踩的 4 个坑

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| `Invalid bound statement (not found): car.insertCar` | `namespace` 或 `id` 写错 / XML 没被加载 | 检查 `mappers` 里的路径、`namespace.id` 是否与调用的一致 |
| `org.apache.ibatis.builder.BuilderException: Error parsing SQL Mapper Configuration` | XML 里 `<!-- -->` 注释写在 DOCTYPE 前面 / 标签顺序错 | 注释写在 `<?xml?>` 之后、DOCTYPE 之前是合法的；重点查标签顺序 |
| `A query was run and no Result Maps were found for the Mapped Statement` | `<select>` 忘了写 `resultType` / `resultMap` | 补上返回类型 |
| 数据没进库，程序无异常 | 忘了 `commit()` | `sqlSession.commit()` 或 `openSession(true)` |
